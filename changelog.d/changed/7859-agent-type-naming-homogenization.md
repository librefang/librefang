Homogenized "agent template" naming to "agent type" across the surfaces that manage the reusable manifests an agent is spawned from.
The handlers behind `/api/templates` are now `list_agent_types` / `get_agent_type` / `create_agent_type` / `update_agent_type` / `delete_agent_type` / `get_agent_type_toml`, the manifests themselves live under `~/.librefang/agent-types/`, and the dashboard's data layer, the TUI's agent-type picker, `librefang agent new` and the docs page were renamed to match.
The HTTP paths themselves are unchanged and stay `/api/templates`: they are a published wire contract, and renaming a URL to match an internal vocabulary buys nothing an operator can use while breaking every script that already calls it.
CLI and API flags that carry a `template` wire contract (`--template`, `POST /api/agents {"template": ...}`) were left alone for the same reason, and workflow templates (`/api/workflow-templates`) are a separate concept that was not touched (#7859) (@DaBlitzStein)
