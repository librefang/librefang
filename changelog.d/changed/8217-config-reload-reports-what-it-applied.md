`POST /api/config/reload` no longer reports work it did not do.
Under `[reload] mode = "off"` or `"restart"` the kernel reads and validates the new config but deliberately never swaps it in, and the response still listed every planned action under `hot_actions_applied` and called the outcome `applied` — the same misleading success that let a revoked credential look revoked while it was still authenticating.
The response now carries `config_applied`, empties `hot_actions_applied` whenever the mode withheld the swap, explains it in `warnings`, and reports `status` as `partial`; the config-file watcher's log line stops saying "applied" for the same case.
`ReloadPlan` carries the answer as `config_stored`, set by the kernel at the line that performs the swap, so callers that publish state derived from the live config read the kernel's own decision instead of re-deriving it from a `[reload] mode` they read at a different instant. (#8217) (@houko)
