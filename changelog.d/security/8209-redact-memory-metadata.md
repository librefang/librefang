Redact the prior versions a proactive memory carries in its own metadata, which every memory read handed back verbatim to callers explicitly denied PII access.
  `ProactiveMemoryStore` writes each superseded version into `metadata.previous_content` and the `metadata.version_history` chain on every in-place update, and redaction rewrote `MemoryItem.content` only — so a `pii_access: false` caller received the e-mail scrubbed out of the current version and handed straight back, unredacted, one key over in the same `GET /api/memory` response.
  `GET /api/memory/items/{id}/history` was worse: the version chain is its entire payload, and it applied no redaction at all.
  Redaction now covers the version chain everywhere `redact_item` already applied — listing, search, per-agent and per-user reads, duplicate groups, and the memories injected into an agent's prompt — replacing each stored version wholesale for a fragment tagged with the `Pii` taint label and regex-scrubbing it otherwise, exactly as `content` is treated, and stamping each rewritten entry so a consumer can tell redacted text from stored text that merely looked like the marker.
  The history route now reads through a guarded store wrapper, so its namespace gate and its redaction cannot drift apart the way the gate alone did.
  Bulk export is deliberately unchanged: it gates on the stronger `export` capability precisely because it dumps raw rows, and a caller holding `pii_access` still sees prior versions exactly as stored (#8209) (@houko)
