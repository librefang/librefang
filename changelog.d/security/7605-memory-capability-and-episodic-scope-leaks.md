Made the automatic-memory scoping of #7605 and #5227 hold on the paths that carry most of a store, which it did not.
`capabilities.memory_read = []` gated only `auto_retrieve`, so an agent an operator had locked out of its own memory still got every stored row rendered into its system prompt on every turn — the substrate recall and the context engine are the other two ways a memory reaches a prompt, the kernel builds a context engine unconditionally, and neither consulted the capability.
On a shared agent that is one visitor's rows arriving in the next visitor's prompt, which is the leak the capability was added to close.
`capabilities.memory_write = []` had the mirror hole: it stopped the extractor but not the per-turn writer, so the store kept growing one verbatim exchange per turn.
That writer also stored its rows with empty metadata, carrying neither the `chat_scope` nor the `session_scope` stamp that `auto_memorize` puts on the facts it extracts, and both recall filters read an unstamped row as visible from every chat and every session.
Raw dialogue is the dominant class in a mature store — 794 of 999 live rows on the installation measured in #7920, each one inlining a whole user turn and the reply — so the isolation was separating the smaller and less revealing half while the verbatim exchanges crossed freely.
Both gates now cover every automatic path, and the per-turn writer stamps both scopes, spelled byte for byte as `auto_memorize` spells them so that an exchange and the fact extracted from the same turn stay recallable from exactly the same places.
Two consequences to know before upgrading: an agent running `session_mode = "new"` no longer recalls raw dialogue from its earlier invocations, and a channel agent no longer recalls a group chat's exchanges in a DM with the same peer.
Both are what those settings already meant for extracted facts; an agent that wants one pool across its sessions sets `session_scoped_recall = false` in its `agent.toml`, as before.
Rows written before this stay unstamped and remain recallable from everywhere, so upgrading never blanks out an existing store — the isolation applies to new writes.
Three boundaries this deliberately does not move, stated so that nobody reads more into `memory_read = []` than it grants.
The `memory_semantic_*` tools keep their separate #7808 gate, which treats a declared-empty list as undeclared and so leaves `memory_semantic_search` on a denied agent's tool list: automatic recall stops, an explicit tool call still reads the store, filtered by neither chat nor session.
A custom context engine's `ingest` hook — `ScriptableContextEngine` and `SidecarContextEngine`, both operator-installed — no longer runs at all for a denied agent, because the gate returns before the engine is consulted rather than filtering what it returned.
And the scriptable `after_turn` hook's own memory injection stays un-gated and un-stamped, so rows an operator's hook writes remain visible from every chat and every session; closing that means changing the `ContextEngine::after_turn` signature, which carries neither a manifest nor either scope.
