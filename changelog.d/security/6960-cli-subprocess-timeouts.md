The Codex, Gemini, and Qwen Code CLI drivers spawned their subprocess with an unbounded `.output()`/stdout-drain call, so a hung or malicious CLI process could block a request — and its stdout/stderr reader tasks — indefinitely.
Subprocess execution is now bounded by a configurable per-driver timeout (`with_message_timeout`, defaulting to 300s, overridable per request), enforced via a shared `output_with_timeout` helper that kills the child and aborts its pipe-reader tasks on deadline, and the qwen-code streaming path now applies the same deadline to its line-by-line reads and final wait/drain (#6960) (@houko)
