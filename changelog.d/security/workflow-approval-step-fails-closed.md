A workflow step with `mode = "approval"` now actually stops the workflow and waits for a human, instead of logging a warning and running everything after it.
The step was accepted by the API, accepted by `Workflow::validate`, previewed by dry-run as a healthy node, and then skipped at run time — it recorded itself as a completed step with no error and its input echoed as its output, which is indistinguishable in the run history, the API and the dashboard from a person having approved it.
Anything an author put behind the gate — a deploy, a payment, a publish, a delete — therefore ran unattended, and the operator had no way to tell, which makes a gate that silently does not gate worse than having no gate at all.
Approval steps now run the same human-in-the-loop executor as `mode = "operator"`: the run suspends, the artifact and the approve/reject choice are pushed to every configured recipient, and it is resolved through the existing `GET` / `POST /api/workflows/runs/{run_id}/operator` endpoints and the pending-review worklist.
An approval that carries a `timeout_secs` fails the run when the budget expires rather than auto-approving, because nobody answering is not an approval.
A suspended run is no longer reported as a finished one either: `POST /api/workflows/{id}/run?wait=true` answers `202 {"status":"paused"}` instead of `200 {"status":"completed"}`, and the chat command, the manual and scheduled cron fires, and the `[ASYNC_RESULT]` event an agent gets back from `workflow_start` now all say the run is parked on a gate and label the pre-gate artifact as such.
The DAG executor, which never matched on step mode and would have dispatched an `approval` or `operator` node to an LLM like any agent step, now refuses to start such a run before any step executes — that path was reachable because `Workflow::validate` rejects only a gate that itself carries `depends_on` while the DAG executor is selected whenever any step in the workflow does, and because validate runs only on the two HTTP registration routes and not on the `*.workflow.toml` files auto-registered from disk at boot (@houko)
