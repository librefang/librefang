`GET /api/mcp/servers` and `GET /api/mcp/servers/{name}` now require the `Admin` role, and are no longer served without authentication when `require_auth_for_reads` is unset.
Both return each server's transport verbatim — a stdio server's `command` and `args`, and an SSE / HTTP server's `url` with its path, query and userinfo intact — and a remote MCP endpoint's credential normally lives in that query string, so on a default configuration the listing handed a set of live bearer tokens to any caller that could reach the port.
#6630 and #6612 already removed the `env` values and the static `http_compat` header values from the same payload; the transport `url` is the one field that cannot be redacted the same way, because the dashboard hydrates its edit form from this response and a scrubbed scalar `url` is indistinguishable from an operator setting that origin deliberately.
Operators who relied on a `Viewer` seeing the MCP page will need to raise that account to `Admin`; every control on the page was already `Admin` or `Owner`, so the page was read-only for those roles before this change. (#8302) (@houko)
