Model routing now says when Stable mode makes it inert, at the place an operator sets it rather than only in the execution path.
Stable mode freezes model choice: the kernel runs neither the profile router (`mode = "flexible"`) nor the tier router (`[routing]` / `[default_routing]`) and applies only `pinned_model`, falling back to the manifest model.
Until now the routing endpoint, the agent detail and both dashboard editors accepted and displayed routing settings as though they would apply, so an operator could configure routing that never ran with nothing on any surface saying so, the same class of silent no-op that `skills/reload` had before #6540.
`GET` and `PUT /api/agents/{id}/model_routing` and `GET /api/agents/{id}` now carry `routing_inert_reason` (`"stable_mode"`, or `null` when routing is live), the routing endpoint also returns `pinned_model` so a client can name the model that actually runs, and the dashboard's Routing tab and the create form's Routing section show a warning while the kernel is in Stable mode.
A save still succeeds and persists, because the setting is valid and takes effect once the kernel leaves Stable mode (#8446) (@houko)
