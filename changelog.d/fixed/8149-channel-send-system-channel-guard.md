Stop suggesting `channel_send` on the kernel-internal channels `webui`, `cron` and `autonomous`, where no messaging adapter exists and the suggestion only pushed the agent into a send that could not succeed.
Each of those channels now gets guidance that matches what the daemon actually does with the turn: a `webui` reply reaches the browser only by embedding the `/api/uploads/...` URL the generating tool returned, and a background run has no interactive chat to reply into — but its response is still delivered to a person whenever the cron job configures a target, so the prompt no longer claims nobody reads it.
`notify_owner` is not offered as a fallback on those runs, because the notice it queues is read only by the interactive API surfaces and is dropped on the cron and autonomous paths.
The three channels are matched by name rather than through the shared reserved-channel-name list, which exists to keep externally-supplied names from colliding with kernel-derived session ids, so a name added there later does not inherit background-run guidance by accident (#8149, #6504) (@DaBlitzStein)
