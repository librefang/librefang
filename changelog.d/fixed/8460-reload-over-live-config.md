A config reload deserialized the on-disk document over the compiled defaults, so a document that parsed but was *partial* reset every field it did not mention: `home_dir` and `data_dir` moved back under `~/.librefang`, and `api_key` reverted to the empty default.
That is reachable from the API's own config-write path, which rewrites only the sections it owns, so on a kernel whose config file did not exist yet the first user or identity edit leaves a `config.toml` stating one section and nothing else — and a deployment supplying its token through `LIBREFANG_API_KEY` has one that no file states.
The document is loaded over the running config now, one top-level key at a time: a key the document states replaces the live value wholesale — so a stated `[provider_api_keys]` table drops the entries it omits, and revoking a key lands on reload — and a key it omits keeps the running value. A stated top-level key spelled with a documented serde alias (`listen_addr`, `approval_policy`) is recognised as the same field as its canonical name. A plan whose only change needs a restart is stored rather than discarded, which is the defect the `queue` and `registry` splits had already fixed one field at a time (#8460) (@DaBlitzStein)
