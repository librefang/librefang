Stop double-formatting agent-initiated channel sends to adapters that do their own Markdown conversion.
`channel_send`, cron delivery, owner and approval notifications, post-approval replies and delegation forwards all ran the outbound text through the kernel's channel formatter without checking `owns_formatting()`, which the inbound reply path has always honoured; for a Telegram sidecar the kernel turned `**bold**` into `<b>bold</b>` and the adapter then escaped the angle brackets, so the recipient saw the markup as literal text, and ordinary prose containing `<`, `>` or `&` was entity-escaped twice.
The outbound path now applies the same gate as the reply path, so an adapter that owns formatting receives raw Markdown and the per-channel `output_format` override applies only to adapters that do not (#8198) (@houko)
