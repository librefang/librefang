`text_to_speech` now takes its default `output_format` from `[tts] output_format` instead of a compiled-in `"mp3"`, so a deployment whose channel accepts only Ogg/Opus voice notes can set it once rather than depending on the model to pass an optional argument on every call.
Only ElevenLabs had a configurable output format; every other provider was pinned to MP3, which a messaging channel rejects as a voice note — and because synthesis itself succeeded and wrote the file, the failure surfaced as a reply that never arrived, with nothing in the log naming the tool or the format.
The key sits on `[tts]` rather than on each provider block because the value never reaches a provider: it selects the post-synthesis ffmpeg step that every provider's audio goes through, and it is the delivery surface, not the provider, that imposes the requirement.
The default is unchanged — unset still means `"mp3"` — and an unrecognised value is now reported by `validate()` at config load, since at the point of use it is indistinguishable from the default (#8274) (@nevgenov)
