A slider's tick legend now places each label over the position its own value occupies instead of spacing the labels evenly.
The legend was a `flex justify-between` row, which distributes labels by count and ignores what they say, so on any range whose ticks are not evenly spread it disagreed with the track directly above it: the context-window row runs 1024..2097152 with ticks at 32K/128K/512K/1M, and it drew "1M" hard right when 1M is the midpoint, and "128K" a third of the way across when its true position is 6%.
Reading a value off the legend was wrong by an order of magnitude.
Each label is now positioned from `(value - min) / (max - min)`, the same expression the filled track uses, and the first and last are pulled back inside the track rather than centred so they cannot hang off either end. (@DaBlitzStein)
