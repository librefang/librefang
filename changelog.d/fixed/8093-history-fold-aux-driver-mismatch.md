History folding no longer sends an agent's model to the wrong provider when no auxiliary chain is configured.
`fold_stale_tool_results` took `AuxClient::driver_for(AuxTask::Fold)` unconditionally, and with no `[llm.auxiliary]` entry that returns `AuxClient`'s primary — the kernel's process-wide `default_driver`, not the triggering agent's chain.
The batched summariser is called with the *agent's* model, so for any agent overriding `provider` / `model` the request went to the default provider carrying a model only the agent's provider can serve: reported as a LiteLLM `403 team_model_access_denied` naming `deepseek-v4-pro` on an agent configured to reach DeepSeek directly, after which every fold silently degraded to the fallback stub and the operator saw nothing but a WARN.
The fold path now branches on the `used_primary` flag `AuxClient::resolve` already returns and falls back to the caller's own driver, which is what `ContextCompressor` has always done for `AuxTask::Compression` (#8093) (@houko)
