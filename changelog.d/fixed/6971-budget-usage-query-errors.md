The usage and budget read endpoints (`/api/usage`, `/api/usage/summary`, `/api/usage/by-model`, `/api/usage/by-model/performance`, `/api/usage/daily`, `/api/budget/agents`, `/api/budget/agents/{id}`, and `/api/budget/providers`) swallowed usage-store query failures with `.unwrap_or_default()` / `.unwrap_or(0.0)`, so a broken SQLite read came back as a 200 with zero spend or an empty list instead of an error.
They now propagate the failure as a scrubbed `500` with a stable `usage_query_failed` code, so a storage problem reads as a failed request rather than a falsely-empty budget (#6971) (@houko)
