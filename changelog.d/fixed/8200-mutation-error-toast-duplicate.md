A failing dashboard write no longer stacks a generic `Error: …` toast on top of the specific message its page already showed.
The global fallback that reports otherwise-silent mutation failures tried to step aside for handlers it could see on `mutation.options`, which carries only the options given to `useMutation` — but nearly every page supplies its error UI per call, as `mutate(vars, { onError })`, and those handlers live on the observer where the mutation cache never sees them.
The fallback now decides after everyone else has had their turn: it records the failure, and one macrotask later — past the observer's call-site handler and past a `mutateAsync` caller's own `catch` — it toasts only if some *other* error toast reached the user in the meantime.
Its own toasts are excluded from that test, so a batch of concurrent failures whose hook and call site both stay silent — the shape of the provider batch test and the goal template batch — still reports each provider's own message instead of collapsing to whichever one failed first.
