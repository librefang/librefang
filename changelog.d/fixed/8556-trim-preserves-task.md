History trimming can no longer drop the current turn's task message.
`safe_trim_messages` only guaranteed that *some* user message survived the trim, so a tiny `max_history` could drain the message that initiated the current turn while an earlier user turn remained — leaving the model to answer a question it could no longer see. The trim now captures the current-turn task before trimming and tests its survival by position (its slot counted from the end of the pre-trim history), not by comparing text: an earlier message with identical text no longer reads as the task, and a task carrying image attachments is no longer dropped by a text-only match. When the task was drained, it is re-inserted ahead of any trailing tool cycle so the model reads task → results and no `ToolUse`/`ToolResult` pair is split. (#8556) (@DaBlitzStein)
