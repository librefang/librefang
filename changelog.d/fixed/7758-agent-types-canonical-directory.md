Agent types (the reusable manifests behind `POST /api/agent-types`, the `agent_type_create` tool, `save-as-agent-type`, and the registry sync) now read and write `~/.librefang/agent-types/` — a directory that exists for exactly this purpose — instead of two directories that were never meant to hold them.
The registry sync used to copy each synced agent type straight into `~/.librefang/workspaces/agents/`, the directory that holds DEPLOYED agent instances with their own sessions and memory; on a real install that manufactured dozens of agents nobody asked to run.
The CRUD API, the `agent_type_create` tool, and the ephemeral/persistent spawn resolvers used to write and read `~/.librefang/templates/` instead, a name already claimed by unrelated starter-TOML scaffolding.
For a fresh install this is the whole fix: agent types land in `agent-types/`, and `workspaces/agents/` only ever contains agents you actually deployed.
For an existing install, nothing already on disk is touched: agents the old sync previously materialized under `workspaces/agents/` are left exactly where they are — they are your agents now, and deleting or moving them is your call, not this fix's.
Likewise, no file under `templates/` is moved or deleted; if any of them look like an agent-type manifest (they declare a `[model]` table), boot now logs a `WARN` naming them and the canonical directory, so you can decide whether to recreate them under `agent-types/` yourself (#7758) (@DaBlitzStein)
