Stop the `Stale PR` and `Issue-PR Link Labels` bookkeeping workflows from cancelling each other's runs across unrelated pull requests.
Both keyed their concurrency group on `github.event.pull_request.number`, which did not isolate one PR from another in practice, so every `pull_request_target` run landed in a single bucket and each new run killed the one before it — one `auto-update-branches` sweep on 2026-09-04 created 33 runs across 33 distinct branches and cancelled 31 of them.
The label bookkeeping itself was unharmed because every run recomputes the desired state from scratch, but a cancelled run reports its check as failed, so nearly every open PR sat at `mergeStateStatus = UNSTABLE` over a housekeeping job while its required `CI Gate` was green, making a real failure indistinguishable from the noise at a glance.
Both groups now key on `github.head_ref`, which varies per PR and is empty outside pull-request events, so the scheduled sweep still shares its constant key (#8190) (@houko)
