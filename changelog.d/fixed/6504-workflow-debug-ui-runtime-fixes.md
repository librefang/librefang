`agent_send` now defaults to non-blocking (`async: true`): it returns a `task_id` immediately and the callee's response is delivered back to the caller's session automatically, instead of blocking the caller's turn until the callee replies and risking the tool-execution timeout on any delegation that takes longer than a few seconds.
  Pass `async: false` when the reply is needed within the same turn for a quick sub-question.
  `channel_send` is no longer suggested to the agent on system channels (`webui`, `cron`, `autonomous`), which have no messaging adapter to route through and previously pushed the agent toward a real channel (e.g. Telegram) that the sender never used.
  Streaming agent invocations now resolve `provider`/`model` `"default"` sentinels and merge default-model `extra_params`, and stamp `sender_chat_id` into the manifest, the same way the non-streaming path already did, so agents spawned post-boot on the streaming path (WebUI, Telegram, forks) no longer reach the LLM API with unresolved sentinel values or lose the chat-id thread needed for async callback routing (#6504) (@DaBlitzStein)
