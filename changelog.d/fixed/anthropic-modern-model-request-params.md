Stop the Anthropic driver putting `temperature` and the `budget_tokens` thinking form on requests to current Claude models, both of which are answered with `400 invalid_request_error` rather than ignored.
Sampling parameters were removed on Opus 4.7 and everything released after it, and extended thinking moved to `thinking: {"type": "adaptive"}` with the depth carried in `output_config.effort`, so an agent pointed at Opus 5, Sonnet 5, Opus 4.8, Opus 4.7 or a Fable model had every single turn die outright — a 400 classifies as `BadRequest`, which the fallback chain propagates instead of failing over to another provider.
Which spelling a model accepts is now decided by one table rather than by string matching at each call site: an unrecognised `claude-*` id is treated as current, because omitting a parameter a model would have accepted costs a default while sending one it removed costs the turn, and an id that is not a Claude id at all keeps the classic schema, because the Anthropic-compatible third-party endpoints this driver also serves — `kimi_coding` and `byteplus_coding` — never lost anything.
On the adaptive form the effort rung comes from `reasoning_mode` alone and is omitted when no mode is set, so an agent that configured nothing keeps the API's own default depth instead of a `medium` derived from a token budget the model no longer has.
The driver also keeps the `signature` Anthropic stamps on thinking blocks, on both the streaming and non-streaming paths, and replays those blocks unchanged at the head of the assistant turn — without that an agent with extended thinking on could not complete a single tool round trip, because the API rejects an assistant turn that dropped a thinking block it produced.
The model that minted a signature is recorded next to it, so a failover leg — which swaps the model while reusing the same history — drops the block rather than replaying it to a model that never issued it (@houko)
