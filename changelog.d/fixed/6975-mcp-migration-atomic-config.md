The MCP migrator wrote the synthesized `[[mcp_servers]]` config with a truncating `std::fs::write`, so a crash or kill mid-write could leave `config.toml` empty or half-written, and the write silently reset the file to mode 0600 regardless of whatever permissions the operator had set on it.
The config is now staged to a unique sibling tempfile, fsynced, and published with an atomic rename; existing Unix permissions are preserved and the parent directory is fsynced afterward so the rename survives a crash, and Windows publishes via `MoveFileExW` with `MOVEFILE_WRITE_THROUGH` for the same durability guarantee (#6975) (@houko)
