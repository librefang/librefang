The `[routing]` tier router no longer scores tool count or system-prompt length, so its decision is a property of the request rather than of the agent's configuration.
Both terms are constant across every turn of a given agent, so they shifted the whole score distribution instead of separating easy turns from hard ones: an agent with ~50 MCP tools collected +1000 from tool count before a single character of the message was read, past any usable `complex_threshold`.
Raising the threshold could not recover it, because trivial messages on that agent were already above it from tool count and system-prompt length alone, so routing degenerated into pinned-complex for exactly the tool-rich agents where cheap-tier routing would have saved the most — and at least one deployment gave up and pinned a model by hand instead.
Scores on existing agents will now be lower; if your tiers no longer separate, lower `simple_threshold` and `complex_threshold` to match, since they are no longer inflated by a constant. (#8075) (@houko)
