`/think on` and `/think off` on a channel now scope the extended-thinking preference to the conversation the command was issued in, instead of to the agent as a whole.
The adapter stored the preference keyed only by `agent_id`, so toggling it in one Telegram chat silently changed the agent's behaviour in every other chat, every group, and every other channel that agent talks on — even though the acknowledgement text already promised "for this chat".
The fix keys the preference by the same `(agent_id, channel, chat_id)` scope `/new`, `/reboot`, and `/compact` already use — the `session_scope` helper and `SessionId::for_sender_scope` — so a toggle in one conversation cannot bleed into another.
The preference remains process-local (an in-memory map on the channel adapter) rather than persisted to the memory substrate: it is a lightweight per-conversation runtime toggle, not durable agent configuration, and a daemon restart resetting it to the manifest default is a reasonable trade-off against adding a persistence path for something a single `/think on` fully repairs.
Adds a regression test pinning the isolation directly: toggling `/think` in one chat_id must not be readable from a different chat_id, a different channel, or the bare channel scope (#7854) (@DaBlitzStein)
