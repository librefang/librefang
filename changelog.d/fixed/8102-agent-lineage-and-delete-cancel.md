Stop the agent detail panel reporting "Root agent" for an agent whose lineage was never fetched, and cancel the queries that actually poll when an agent is deleted.
`GET /api/agents/{id}` carries no lineage, so the panel carries it over from the list row; when the row is a stub — clicking through to a parent the current list does not hold, or the fallback built when the detail fetch fails — the carry-over overwrote the real fields with `undefined` and the render fell through to "Root agent", which is exactly what `routes/agents/mod.rs:377` tells clients not to do with an unknown parent.
Lineage is now carried over only when the source actually has some, a fourth "Not loaded" state is rendered instead of guessing, and the documented `parent` alias is honoured alongside `parent_agent_id`.
Deleting an agent cancelled only `agentKeys.detail(id)`, the single query in that family with no `refetchInterval`; the ones that poll — `stats`, `events` and `sessionContext` — live on sibling branches under `agentKeys.all` and were never matched, so they kept firing at a deleted agent.
The cancel moved into `useDeleteAgent`'s `onMutate`, where it is awaited before the DELETE is sent and sits next to the `onSuccess` removal it pairs with, and now matches every per-agent key. (#8102) (@houko)
