`GET /api/models?provider=<gateway>` returned zero models for a self-hosted OpenAI-compatible gateway (litellm, a vLLM or llama.cpp proxy registered under its own provider id) even when the gateway was reachable and actively serving completions.
Only OpenRouter and EveryAPI got a live catalog refresh; every other provider was served from the checked-in registry snapshot, which by definition cannot ship an operator's own model ids.
The handler now probes the gateway's `/models` listing — the same probe the periodic loop and `GET /api/providers` already run — instead of only *reading* the probe cache it never filled, so a `/api/models` call that arrived before either of those had run no longer reports the gateway as empty.
Where the gateway also answers litellm's optional `/v1/model/info`, the declared capability and capacity figures are used; where it doesn't, the model still appears with the catalog's "unknown" sentinel rather than being hidden, because a missing figure is not evidence the model is absent (#7816) (@DaBlitzStein)
