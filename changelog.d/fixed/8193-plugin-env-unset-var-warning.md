A plugin `[env]` value referencing a variable the daemon does not have now logs the `warn` the plugin documentation has always promised, instead of expanding to an empty string in silence.
An operator who mistyped a name, or forgot to export it into the daemon's own environment, saw a hook read `""` from a variable they believed they had set, with nothing in the log to distinguish that from a deliberately blank value — and the reserved-secret branch added directly above it does log, which would have left the unset case as the only silent path through a function whose purpose is making expansion auditable (#8193) (@houko)
