Mutating CLI commands now exit non-zero when the daemon rejects the write.
`daemon_json_checked` terminates the process only for a transport error; on an HTTP error status it returns to the caller, and `models set`, `models overrides` (both saving and `--clear`), `approvals approve|reject`, `group create|delete|add-member|remove-member`, `webhooks create|delete|test` and the `--set-default` step of `models connect everyapi` printed the daemon's rejection and then fell off the end of the handler with the exit code still at 0.
Because those messages go to stdout, the exit status was the only signal available to a script or agent driving the CLI, so `librefang group create dup-name >/dev/null || fail` read a 409 as a successful create.
`webhooks test` additionally gated its success line on a `success` field that `POST /api/webhooks/{id}/test` has never returned — the route reports delivery as `status = "sent"` — so it now reads the field the daemon actually sends rather than turning every delivered webhook into a failure (#8199) (@houko)
