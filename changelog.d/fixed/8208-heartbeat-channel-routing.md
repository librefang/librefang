Wire `[autonomous] heartbeat_channel` in `agent.toml`, which round-tripped through the manifest, the dashboard form and the generated manifest summary while no Rust code ever read it.
Unresponsive-agent alerts were never lost — they have always fanned out as the `health_check_failed` notification, routed by `[[notification.agent_rules]]` or `[notification] alert_channels` — but an operator who configured only the per-agent field got the global routing or nothing at all, with the dashboard echoing the setting back as if it were in effect.
The field is now a per-agent target for that alert, sitting between the two config layers: a matching `agent_rules` entry still wins, the manifest value is consulted next, and `alert_channels` remains the fallback.
It accepts `"telegram"`, whose recipient comes from the `owner` user's `channel_bindings` entry for that channel, or `"telegram:123456"`; a value that resolves to neither is logged once per unresponsive transition and ignored, so a mistyped knob degrades to the `[notification]` routing instead of swallowing the alert (#8208) (@houko)
