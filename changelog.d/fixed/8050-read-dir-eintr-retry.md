`file_list` and `file_search` now retry a directory read the OS interrupted (`EINTR`) instead of failing the tool call.
An interrupted syscall means the call was cut short by a signal before doing anything and is expected to be reissued by the caller — Python has done this transparently since PEP 475 — but LibreFang surfaced the first interruption as `Upstream error: Interrupted system call`, which reads like the mount died.
On a cloud-synced directory (macOS FileProvider, iCloud-backed `~/Documents`) the read stays in the kernel long enough that a signal is likely to land mid-call, so the failure was effectively deterministic: an agent hit it 6/6 times on a path a concurrent `os.listdir()` loop read successfully 160/160 times, then gave up through the repeated-tool-failure guard while operators went looking at a sync daemon that was healthy the whole time.
`file_search` swallowed the same error by design and so had been silently dropping whole directories from its results rather than failing. (#8071) (@houko)
