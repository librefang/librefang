`workflow_create` now records the calling agent instead of discarding it.
The `caller_agent_id` parameter was threaded all the way from the tool call through `KernelHandle::create_workflow`'s trait signature into the kernel implementation, then ignored there — leaving zero audit trail for a tool that sits in `ALWAYS_NATIVE_TOOLS`, so every agent has it without configuration, and whose sibling `workflow_run` (also always-native) can immediately execute whatever `steps[].agent` the new workflow names.
The kernel now logs it on creation, so a security investigation can trace which agent turn produced which workflow, and separately resolves an owner from the authenticated caller, the agent manifest's `owner`, or `config.toml`'s `default_owner`, logging explicitly when all three are absent rather than recording an ownerless workflow in silence.
The caller and the owner are deliberately two different questions: the first is which turn assembled the spec and stays a log-only trace, the second is who the workflow belongs to (#7857) (@DaBlitzStein)
