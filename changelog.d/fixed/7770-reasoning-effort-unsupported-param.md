Agents behind a gateway that rejects `reasoning_effort` no longer fail every turn and then go silent for the provider cooldown.
litellm fronting an OpenAI-shaped model group returns `400 UnsupportedParamsError: openai does not support parameters: ['reasoning_effort']`, and the driver sent the field for any agent whose manifest carries a `[thinking]` section, since `ThinkingConfig` defaults to a 10000-token budget that maps to `"medium"`.
The OpenAI-compatible driver now recognises an unsupported-parameter rejection — litellm's `UnsupportedParamsError`, OpenAI's own `unsupported_parameter` code, and the `unexpected keyword argument` shape that FastAPI-style proxies surface — strips the field, retries once, and remembers the model so it is not sent there again.
That specific deterministic 400 is also excluded from the `ProviderCooldown` circuit breaker, because backing off cannot change an outcome caused by the request we build; a 400 for credentials, a malformed payload, a nonexistent model or an oversized context still opens the circuit (#7770) (@DaBlitzStein)
