An agent type's `tools` field now actually reaches the ephemeral worker spawned from it.
The worker's tool list was resolved from the spawn request alone, so an agent type saved with `tools = ["shell_exec"]` handed Quick Run a worker with no tools unless the caller repeated the list in the request body — silently making the "Tools" field on the Agent Types form a no-op for that flow.
The worker's set is now narrowed in three stages: the parent's own `available_tools` is the ceiling, the agent type's declared `tools` narrows it when the run comes from a template that declares any, and the request narrows it further when it asks.
Taking the parent's set as the ceiling is what makes the containment provable rather than merely intended — a worker can never call something its parent may not, so a restricted parent cannot launder a privilege escalation through one — and both an empty list and `["*"]` still read as "unrestricted", the same way they do for a permanent agent's manifest (#7875) (@DaBlitzStein)
