The boot-time default LLM driver resolved `base_url` only from `[default_model]` and `[provider_urls]`, so a provider declared in `~/.librefang/providers/<id>.toml` — the file the dashboard writes — failed at boot with "has API key but no base_url configured" and silently fell back to auto-detect.
Boot now resolves the endpoint and the credential environment variable from the same provider catalog the per-turn path uses, with explicit `[default_model]` and `[provider_urls]` entries still winning; operator-explicit `[provider_api_keys]` and `[auth_profiles]` entries keep their precedence.
