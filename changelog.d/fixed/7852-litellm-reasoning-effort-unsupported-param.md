Agents behind a litellm gateway fronting an OpenAI-shaped model group that doesn't forward `reasoning_effort` no longer go silent for five minutes on every turn.
litellm was returning `400 UnsupportedParamsError: openai does not support parameters: ['reasoning_effort']` because `ThinkingConfig` defaults to a non-zero budget on every request, and the driver treated any non-retryable error as a provider-health signal for the circuit breaker.
The OpenAI-compatible driver now recognises an unsupported-parameter rejection — litellm's `UnsupportedParamsError`, OpenAI's `unsupported_parameter` code, and proxy `unexpected keyword argument` shapes — strips `reasoning_effort`, retries transparently, and records the rejection against that provider and model so the next turn does not pay for the same 400 again.
Crucially the provider circuit breaker (`ProviderCooldown`) now excludes this specific, deterministic 400 class from its failure count: a genuine bad-request, auth, or model-not-found 400 still opens the circuit as before, but a gateway that merely declines one optional field is no longer mistaken for a gateway that is down (#7852) (@DaBlitzStein)
