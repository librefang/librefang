Remote MCP servers that follow the MCP authorization spec could not be connected: the `resource_metadata` document was parsed as authorization-server metadata, so it failed (it only names issuers), its `authorization_servers` were never followed, and the fallback only tried the origin-root well-known URL — a server behind a path prefix answers that with its web app. Discovery now follows `authorization_servers` and tries the RFC 8414 path-inserted URL first, then the in-path and OIDC variants; a `registration_endpoint` found along the way is kept, so dynamic client registration still runs and the dashboard can show Authorize.
