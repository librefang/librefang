Session and cron compaction no longer send an agent's model to the kernel's default provider.
Both call sites took `AuxClient::driver_for(AuxTask::Compression)` unconditionally and paired it with the agent's own model, and with no `[llm.auxiliary]` entry that driver is `AuxClient`'s primary — the process-wide `default_driver`, not the triggering agent's chain — so any agent overriding `provider` / `model` had its model sent somewhere that cannot serve it, degrading silently to the fallback summary behind one WARN.
The rule now lives in a single `side_task_driver` helper: an explicitly configured aux chain still wins, and otherwise the task runs on the agent's own driver, which is the behaviour the comment at the compaction call site already claimed.
The comment was the bug's origin — it asserted that the unconfigured resolver returned something "equivalent to `resolve_driver(&entry.manifest)`", which is only true for an agent running the kernel default (#8093) (@houko)
