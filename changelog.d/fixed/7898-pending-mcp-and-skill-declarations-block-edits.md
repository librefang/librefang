Saving an agent's MCP server or skill allowlist from the dashboard no longer fails with a 400 "Internal error" when the list includes a name that is declared but not yet installed or connected.
A declared-but-not-installed MCP server (present only in the local MCP catalog synced from the registry, or configured in `config.toml` but not yet connected) is now accepted and persisted as a pending declaration, exactly like `spawn` already does — saving it never installs, connects, or otherwise mutates `config.toml`.
Skills get the equivalent treatment for a skill directory present on disk but not yet loaded into the running registry (`SkillRegistry::unloaded_on_disk_dirs`); this is narrower than the MCP fix because skills have no locally cached catalog of everything that could be installed the way MCP servers do.
A name absent from every known source is still rejected, now as `LibreFangError::InvalidInput` (400) with a message naming the rejected entry, instead of the misleading `Internal` variant.
Previously the whole allowlist save failed the moment it hit the first unrecognized name, so an agent that had accumulated even one pending declaration (e.g. `fetch`, shipped as a default MCP server on some agent-type templates but never installed) could not be edited from the dashboard at all (#7898) (@DaBlitzStein)
