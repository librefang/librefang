Restore the leading-user invariant after the context engine trims a session from the front, which strict providers require and the engine path had stopped guaranteeing.
`DefaultContextEngine::assemble` re-paired tool calls with `validate_and_repair` after an overflow drain but never ran `ensure_starts_with_user`, unlike every sibling post-trim site in the agent loop.
Stage 1 recovery keeps only the last ten messages, and in a tool-heavy history that boundary lands on an assistant turn about half the time, so the first message sent to the model was `role: model` — which Gemini and Vertex AI reject outright with `400 INVALID_ARGUMENT`.
A context engine is wired for every agent by default rather than only when `[context_engine]` is configured, so there was no setting to turn off to work around it, and because the drained history is a per-turn working copy the same request failed again on every subsequent turn until the session was compacted or reset.
The repair is applied only when it leaves a user turn behind: on a window of nothing but tool-call pairs it cascades — dropping the leading assistant turn orphans the tool result that answered it, which empties the user turn carrying that result, which orphans the next pair — and `assemble` has no user message to synthesize a replacement from, so the unrepaired history is kept rather than sending an empty request body that every provider rejects (#8197) (@houko)
