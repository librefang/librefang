The per-turn `prompt cache metrics` line is now emitted for every turn that finishes through the loop's exit paths, in both the streaming and the non-streaming loop, not only when the turn reached the normal end-turn path.
  Capped turns, continuation-truncated turns, interrupted turns, silent turns (no-reply, cascade-leak, progress-leak) and turns that fail on a provider, tool or content-filter error previously wrote no line at all, so a per-agent hit-rate trend silently omitted exactly the turns an operator opens the log to diagnose; the streaming half mattered most, because channel bots stream.
  The event moved into `log_cache_metrics`, and its `outcome` field says how the turn ended (`completed`, `max_iterations`, `max_continuation`, `silent`, `repeated_tool_failures`, `content_filtered`, `circuit_break`, `error`), so the new rows can be filtered out of a trend that used to cover completed turns only; the label comes from the same `classify_ok_outcome` / `classify_error_reason` pair that feeds `librefang_agent_loop_exits_total`, which therefore now reports `reason="silent"` for turns it used to fold into `completed`.
  Telling a continuation-truncated turn apart from a completed one needed a flag on `AgentLoopResult` (`truncated_by_continuation`), because the reply is otherwise an ordinary `Ok` — the same shape `hit_iteration_cap` already had for the tool-loop budget.
  It stays silent when a turn reported no tokens at all — a failure before the first model call, or a driver that does not report usage.
  One exit stays unaccounted for and is documented rather than claimed away: an `Err` that escapes through `?` (context assembly mid-turn, and the session saves on the silent paths) carries usage but writes no line.
