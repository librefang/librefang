A fallback chain slot left with `model = "default"` sent that literal string to the provider instead of resolving it, producing errors like "Invalid model name passed in model=default".
The fallback resolution loop already resolved `provider = "default"` to the operator's configured default provider, but never applied the same resolution to `model`, so a fallback entry with an explicit provider and no explicit model (the common shape — only `provider` gets set, `model` is left at its zero value) reached the driver unresolved.
The fix resolves `model` first, then infers `provider` from the resolved model name when `provider` itself is `"default"` or empty — inferring from the raw unresolved `"default"` string always failed silently and masked a real per-model provider hint (#7798) (@DaBlitzStein)
