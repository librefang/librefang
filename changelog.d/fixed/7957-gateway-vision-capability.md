Stop guessing whether a model behind an OpenAI-compatible gateway can see images, and stop dropping the images when the guess says no.
An operator names a LiteLLM or vLLM deployment whatever suits them — `team-default`, `fast`, an internal ticket id — and nothing in such a name says anything about vision, but the catalog inferred `supports_vision` from it anyway and the agent loop acted on that inference: every image was replaced by a placeholder holding the file's path, and the turn then succeeded.
That is worse than an error, and worse than the HTTP 400 a genuinely text-only endpoint would have returned, because a failure gets diagnosed while a plausible answer gets believed — the model describes the picture from its filename and nobody has any reason to look.
A catalog *miss* had always failed open and kept the images, so the only models this could reach were the ones the catalog thought it knew about.
Capability flags a gateway publishes are now read and believed in both directions (LiteLLM's `supports_vision` / `supports_function_calling`, OpenRouter's `architecture.input_modalities`), an inferred flag is recorded as the guess it is and resolves to "unknown", and unknown sends the images exactly as a miss does.
Only a model something actually declared text-only is still redacted, and that redaction now logs a `WARN` naming the model, the number of blocks replaced and the override that fixes it.
`librefang everyapi connect` was doing the same laundering through a different door — a gateway model missing from the bundled snapshot was written to `providers/everyapi.toml` as declared blind — and now records it as unknown too (#8087) (@houko)
