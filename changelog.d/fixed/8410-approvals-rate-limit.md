Approving a batch of tool calls no longer answers `429 Too many login attempts` and locks the operator out of their own dashboard for the rest of the fifteen-minute window.
  The per-IP auth limiter counts requests before the handler runs, so it was spending the operator's login budget on approvals that had already succeeded, and `approve_request` only verifies a TOTP or recovery code when the approval policy requires one for the tool being approved (`approval.second_factor`, narrowed by `approval.totp_tools`) and the caller is outside the TOTP grace window — with the default `none` there was no credential on that path to brute-force, and a policy-wide answer kept metering approvals that verified nothing.
  `/api/approvals/{id}/approve` is now metered per request, on the same tool-and-grace question `approve_request` and `resolve` enforce, which keeps the #4020 protection exactly where it applies (#8410) (@DaBlitzStein)
