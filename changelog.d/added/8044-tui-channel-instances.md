A Channels screen in the TUI that manages `[[sidecar_channels]]` instances directly — list them grouped by adapter type with per-instance health and assigned agent, add one, edit one, delete one.
The backend has accepted several instances of a single adapter type for a while, so two Telegram bots bound to two different agents were always possible; what was missing was any way to say so other than opening `~/.librefang/config.toml`.
That mattered more than a convenience gap, because a hand-written instance is easy to get subtly wrong: the block's `name` and its `channel_type` are different identifiers, secrets belong in `secrets.env` under a per-instance prefix rather than inline, and an edit only takes effect after a channel reload.
The screen sends the adapter where the API wants an adapter and the instance name where it wants an instance name, so the two cannot be transposed, and it refuses a name that collides with an existing instance before issuing a request rather than surfacing the daemon's 409.
The same distinction fixed three real bugs in `librefang channel setup`, which sent a configured row's instance name into a path that only accepts a catalog adapter (a 404 for any instance not named after its own adapter), dropped the instance's `agent` binding on every save because an absent `agent` field means "clear it", and promised that a blank required secret would keep the stored one when the daemon rejects that with a 400 (#8082) (@houko)
