New `librefang purge --agent <name>` CLI command removes every trace of an agent the operator already deleted: any roster entry left over (cascading to its sessions, memories and KV rows), rows a previous partial delete orphaned even when the roster entry is already gone, the agent's canonical UUID record in `agent_identities.toml`, the workspace directory, and any agent-type template of the same name.
  The orphan scan walks the same shared table list the substrate's agent cascade deletes from, so residue in tables the cascade only learned about later — `pending_approvals` (v26), `goal_runs` (v42), `usage_events` — is found rather than reported as "no trace in this installation", which is the state older installations are actually in.
  The workspace directory is resolved the way spawn resolves it, through `workspaces_dir` and the agent's own `workspace` override, so a relocated workspace is purged instead of quietly surviving a run reported as successful; an orphan has no manifest left to read, and the report says the location was not resolvable rather than claiming there was nothing there.
  Agent names are only required to be a single path component, so an agent named `my.bot` or `研究员` can be purged like any other.
  The command prompts for confirmation over the plan it just computed rather than a fixed warning (with `--yes` to skip — required when stdin is not a TTY), asks nothing when there is nothing to purge, and offers `--dry-run` to print the exact `PurgeReport` it would produce without changing anything (#7986) (@DaBlitzStein)
