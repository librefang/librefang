The Memory tab of the TUI had no way to see or change which model writes memories, so an inherited default that ran after every reply and blew past its own ceiling held every answer for minutes with no surface naming the cause.
The tab now has a configuration panel that shows the resolved extraction model and its provenance alongside the search provider, and lets `auto_memorize`, `auto_retrieve` and the extraction model be edited and saved back through `PATCH /api/memory/config`.
The unsaved-changes marker survives until the daemon confirms the write, so a refused save reads as unsaved work with the status code and body that refused it, not as "everything is saved"; attached in-process, where there is no HTTP surface to PATCH, the panel says so instead of sitting on "Saving..." forever.
