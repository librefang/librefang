The Skills drawer now renders the skill version store's real history: every recorded write to a skill — create, evolve, patch, rollback, install/uninstall, delete, supporting-file changes and restores themselves — as a newest-first list with the stored timestamp, author and labelled `change_source`, each row expandable to the snapshot's `skill.toml` and prompt context.
Restore writes a snapshot's files back over the skill's current ones after a destructive confirmation that names the version about to be applied; the restore itself is recorded as a new history entry, so the list keeps the evidence of what replaced what.
The change-source labels come from a new closed `skills.change_source` map (verbatim fallback for tokens the dashboard does not know), and the store-backed list is shown first and the file-based `.evolution.json` list remains as a fallback when a legacy skill has no stored rows; only store rows can be restored.
