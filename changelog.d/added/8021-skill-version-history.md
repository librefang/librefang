Skills now keep a version history, so an operator can see how a skill's `skill.toml` and `prompt_context.md` changed over time and put a prior state back.
Every mutation surface records: the dashboard's evolve endpoints (create / update / patch / rollback / delete / supporting-file writes), the agent-facing `skill_evolve_*` tools, the skill-workshop approve and background-reviewer paths, and install/uninstall. Each row names the operation (`change_source`) and the surface that made it (`author`, e.g. a user name, `agent:<id>` or `reviewer:agent:<id>`), so the history distinguishes an interactive edit from an automated one.
`GET /api/skills/{name}/history` lists snapshots newest-first (default 30, max 200) and `POST /api/skills/{name}/history/{version_id}/restore` writes a snapshot's `skill.toml` + `prompt_context.md` back under the same per-skill lock as every other mutation and records the restore as its own snapshot.
Retention is 50 rows per skill, trimmed on insert in the same transaction; identical `(manifest, prompt, source)` re-writes dedupe, while `restore`, `file-write` and `file-remove` always record — their row is the event.
v1 keys history by skill name alone and covers the global `~/.librefang/skills/` root: hand-scoped and workspace skills are not recorded yet, and neither are CLI/TUI writes that bypass the daemon.
