Add the `workflow_create` tool so agents can author a reusable workflow during a conversation, where previously a workflow could only be created through the dashboard canvas, the CLI, or the HTTP API.
The tool is always-native, so every agent has it without configuration; it validates the workflow name against the shared `[A-Za-z0-9_-]`, 1-64-character rule at both the runtime and the kernel layer, runs the same `Workflow::validate()` semantic checks the HTTP API runs, and registers the result in the engine so `workflow_run` and `workflow_start` can reach it immediately.
Creation is capped at 50 steps, a 1-hour per-step timeout, and a 24-hour whole-workflow timeout, enforced in the handler rather than only advertised in the JSON schema, because a schema ceiling is advice the calling model is free to ignore.
The kernel logs the calling agent alongside the registered workflow, so a workflow an agent synthesized can be traced back to the turn that produced it. (#6943) (@DaBlitzStein)
