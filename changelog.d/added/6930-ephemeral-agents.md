`agent_spawn` gained an ephemeral mode for disposable sub-agents: a temporary worker, built from a stored agent type or from inline fields, runs one task and hands the result straight back to the caller with no workspace directory and no registry entry, and its token spend is billed to the agent that spawned it.
The same worker is reachable over HTTP as `POST /api/agents/spawn-ephemeral`, under the inter-agent recursion-depth guard and a clamp on the requested iteration count so an untrusted caller can neither stack workers nor ask for an unbounded loop.
The billed agent's own cost quota is what actually gates the run (previously only the throwaway worker's own, effectively unlimited, quota was checked), the worker's turn runs incognito so it leaves no session or memory row behind, `agent_type` can no longer be used to borrow another agent's identity and credentials, a caller-supplied `base_url` / `api_key_env` override is refused unless it matches something the operator already configured, and the direct HTTP route can attribute cost to a specific agent's budget via an optional `parent_agent_id` field instead of always billing the throwaway worker (#6930) (@DaBlitzStein)
